# 0196: "upscale to the screen" (MetalFX spatial), Direct3D 11 and 12, with frame generation

Until now the app only set DXMT's fixed factor (`d3d11.metalSpatialUpscaleFactor`, 1 to 2, Direct3D 11 swap chains only), so Direct3D 12 games (GTA V Enhanced) got no upscaling at all, a game drawing at the screen's own size was enlarged to twice the screen, and the person had to work out the factor.
* **DXMT** (`d3d11_swapchain.cpp`): `DXMT_METALFX_FIT = "<w>x<h>"` (the screen's pixels, set by the app) makes `MetalFXFitFactor` pick the factor: `min(screen_w / game_w, screen_h / game_h)`, at most 2, and 0 (no scaler, the plain swap chain) when it is under 1.1. Used by the swap chain's constructor and by the factory that chooses the MetalFX variant. `[upscale] to the screen: WxH -> xF` in the log.
* **Direct3D 12** (`madeira_d3d12.c`): madeira.cfg `metalfx-upscale = fit:<w>x<h>` does the same (a plain number is still a fixed factor). The Lossless Scaling bridge no longer refuses a swap chain with a scaler: each generated picture goes through the same scaler (`MTLCommandBuffer_encodeSpatialScale` on the generated texture, any 2D texture of the scaler's input format) into `fx_out` before it is copied to the drawable.
* **App**: Game details > Upscaling: "To the screen" (stored as `upscaleFactor = 0`), 1.5x, 2x. `EngineLaunch.screenPixels()` gives the pixels; the madeira.cfg key is removed again when the setting goes off (`f4.upscaleCfgSet`).
Not verified on a device. Rebuild: `ninja -C dxmt/build-arm64ec-r29 src/d3d11/d3d11.dll`, strip, `build/madeira-d3d12/build-pe.sh`, copy `d3d11.dll`, `d3d12.dll`, `madeira_d3d12.dll` over `ec-out-r29/` and the stage. `tools/engine.sh accept`.
