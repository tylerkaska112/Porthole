# 0157 DXMT (PE d3d11.dll): ResizeTarget / SetFullscreenState / updateFullscreenWindow really size the window

`dxmt/src/util/wsi_window_headless.cpp` (the window-system file the ARM64EC d3d11.dll is built from, see `src/util/meson.build`): `resizeWindow`, `enterFullscreenMode`, `leaveFullscreenMode` and `updateFullscreenWindow` were no-ops that returned success. They now do what native DXGI (and `wsi_window_win32.cpp`) does, with one rule that keeps every game that works today unchanged: a window that already has the asked client size, or already covers the screen, is left alone. A resize never goes beyond the screen. Everything it does is logged as `[wsi-0157]` (WARN lines).

Reason (American Truck Simulator, 2026-10-17, builds 1.1.15-1.1.18): ATS creates a placeholder window with a 1x1 client area, strips its border and expects DXGI to make it screen sized (full screen) or the asked size (ResizeTarget). The no-ops left it 132x38 while the game rendered 1920x1080 into it. Patch 0156's raw window log showed the game never calls SetWindowPos with a size (`[winreq]`), and that its borderless setup uses only NOSIZE calls.
Build: `meson setup <dir> dxmt --cross-file dxmt/build-arm64ec-win.txt --native-file dxmt/build-osx.txt -Dwine_build_path=<abs>/wine/build-arm64ec -Dbuildtype=release` from `vendor/Madeira`, `ninja -C <dir> src/d3d11/d3d11.dll` (PATH needs `toolchains/llvm-mingw-*/bin`, SDKROOT the macOS SDK; about 15 s), `arm64ec-w64-mingw32-strip` into `$F4_BUILD_ROOT/ec-out/d3d11.dll` (the previous file is kept as `$F4_BUILD_ROOT/d3d11.before-0157.dll`). The old build directory `dxmt/build-arm64ec` points at another checkout; the new one is `$F4_BUILD_ROOT/dxmt-ec-0157`.
Unverified on a device. UNKNOWN: whether ATS calls ResizeTarget or SetFullscreenState at all (if it does neither, the `[wsi-0157]` lines will be missing and the window stays tiny), and whether a fullscreen DXGI game that currently works is affected (it should not be: its window already covers the screen).
