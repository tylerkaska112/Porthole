# Known-problem fixes for individual games

Some games have one specific problem that a tiny workaround avoids. Porthole applies it automatically just before that game starts (`app/Sources/Core/GameFixes.swift`).
A fix either sets aside a file inside that game's own folder (renamed with `.porthole-disabled`; nothing is deleted or edited) or tells Wine not to load a library for that game (`WINEDLLOVERRIDES`, set only for that launch). Each is logged as `[game-fix]` in Settings ▸ Log.
Verifying or updating the game in Steam brings the file back; Porthole sets it aside again at the next launch. To undo a fix yourself, remove `.porthole-disabled` from the file name.

| Game | Steam app | What is set aside | Why |
|---|---|---|---|
| The Forest | 242760 | `TheForest_Data/Plugins/OVRPlugin.dll` (and the same name in `TheForest_Data/Mono`); Wine is told not to load `avrt.dll` | The pool leaks twice. 1) Unity tries to load the Oculus VR plugin six times. It can never load here (it needs Windows video libraries that don't exist), and each failed attempt still uses about 28 MB of the emulator's code pool, which is only returned when a whole emulated process exits. After six attempts plus the other libraries the 624 MB pool is full and the game freezes at the menu (fixed in 0.50.3: it then reached the loading screen). 2) Once the world loads, Unity's short-lived threads (about 400 in a session) each load `avrt.dll` (0.5 MB) and unload it again; 292 reloads used 146 MB and filled the pool a second time (0.50.4). Diagnosed from two device logs, 2026-10-03. |
| Assetto Corsa | 244210 | nothing hidden; started without Steam's launch, running `acs.exe` instead of `AssettoCorsa.exe`, with its own Steam app id and folder published | `AssettoCorsa.exe` is a .NET launcher. Wine has no Mono here ("Wine Mono is not installed", then the program exits with code -1). Starting through Steam fails too: Valve's client signs in, then refuses with launch error 17 ("content this game depends on"), and would run the same launcher. The game is `acs.exe` (32-bit). Found from two device logs, 2026-10-03; whether `acs.exe` also needs a running Steam client is untested. |
| Rust | 252490 | nothing hidden; `RustClient.exe` is started next to Valve's signed-in client instead of asking Steam to launch `Rust.exe` | `Rust.exe` starts Easy Anti-Cheat, which does not run here. `RustClient.exe` is the game and plays on servers that do not require it. Valve's client only starts what its launch list names, so the Dock host (patch 0075) starts the program itself, inside the verified install folder, with Steam's client running and `SteamAppId` set. Not verified on a device. |
| Supermarket Simulator | 2670630 | nothing hidden; the engine's automatic texture saver is switched on for this game (`MADEIRA_MIP_CLAMP_AUTO=1`) | A Unity game with hundreds of block-compressed textures. An iPad with an A15 or A16 chip cannot sample those, so each is decoded to uncompressed RGBA (four to eight times its size): on a 6 GB iPad, loading a save took the app from 1.5 GB to 4.1 GB in 21 seconds and iOS closed it. With the switch on, large textures lose their top detail level once the app is within 1.5 GB of its limit. |
| The Witcher 3: Wild Hunt | 292030 | nothing hidden; AVX and AVX2 are switched on for this game (`MADEIRA_FEX_AVX=1`) | The current version runs AVX instructions without checking for them; with AVX off it ended on the first one (`c000001d`, compatibility report #139). |
| Dying Light 2 Stay Human | 534380 | nothing hidden; AVX and AVX2 are switched on for this game (`MADEIRA_FEX_AVX=1`) | `DyingLightGame_x64_rwdi.exe` runs AVX instructions without checking for them; with AVX off it ended on the first one (`c000001d`, compatibility report #146). |
| Subliminal | 2300840 | nothing hidden; the engine writes the Visual C++ ARM64 registry marker for this game (`MADEIRA_VCRT_ARM64_KEY=1`) | An Unreal Engine game that checks for "Microsoft Visual C++ 2015-2022 Redistributable (arm64)" at start-up and stops with a message when the marker is missing. There is nothing to install: the check only reads the marker. |
| BeamNG.drive | 284160 | nothing hidden; started with `-forceUltralight` (its own menu engine, no Chromium) and engine settings for that launch only (`MADEIRA_SC_PA_POOLS=2`, `MADEIRA_GLUED_MAIN=1`, `MADEIRA_X64_IMAGE_NOCOPY=1`, `MADEIRA_CAGE_RELEASE=1`, `MADEIRA_LOCK_ORPHAN=0`, plus `MADEIRA_CHILD_ARGS` for the switch and some Chromium switches left over from earlier attempts that the menu no longer reads) | The game's Chromium menu cannot start here: its helper processes each ask for a 32 GB memory pool and there is room for two. The game also has Ultralight, a smaller menu engine, behind `-forceUltralight`; the engine patches 0151-0155 give Ultralight the memory it asks for and the game a monitor size. |
| FINAL FANTASY RESONANCE and its demo | 3259780, 4474710 | nothing hidden; the game's own lines `env.MADEIRA_VCRT_ARM64_KEY = 1`, `env.MADEIRA_X64_IMAGE_NOCOPY = 1` and `pool-split = 1` are added (the split pool makes up for the code pool the kept window leaves in two pieces: a start gave 416 of 896 MB, and Porthole refused to start); the 0x140000000 window is kept because the program below the main folder needs it | The first program (FFRS.exe) is an x64 Unreal Engine start-up that checks for the Visual C++ 2015-2022 runtime and, because Windows is reported as ARM64 here, asks for the ARM64 version and stops; the marker line fixes that (the demo passed it on 1.2.86). The game itself, `FFRS/Binaries/Win64/FFRS-Win64-Shipping.exe` (487 MB), loads at 0x140000000 with no relocations: with that range given back to the code pool the demo ended with status c0000018 ("failed to create main module"), because only the launcher in the main folder had been read. ExecutableWindow now reads the folders below it (four deep, installers and runtimes left out). Found from user logs, 2026-11-03; not yet confirmed on a device. |
| Megabonk | 3405340 | nothing hidden; the game's own lines `env.MADEIRA_REAL_SUSPEND = 1` and `env.MADEIRA_WGI_HOST_PADS = 1` are added, and Automatic keeps the Xbox pad | Unity IL2CPP: the game does not start without real thread suspension. Its input is Rewired with the Windows.Gaming.Input plugin, which asks for gamepads only; the host pad was one only as an XInput slot, so no controller mode worked except keyboard and mouse. |

Any Unity game with `Rewired_WindowsGamingInput.dll` under `<name>_Data/Plugins` gets the Windows.Gaming.Input line and the Xbox pad automatically (`GameFixes.usesRewiredWindowsGamingInput`); your own `env.MADEIRA_WGI_HOST_PADS` line wins.

The proper cure is in the engine (give pool space back when a library fails to load or unloads); see `docs/ENGINE.md` for what a change there means for compatibility badges.

The thread-table half of The Forest's trouble is fixed in the engine instead (`patches/0012-thread-registry-reuse.md`, engine 40d5e74-r1): about 2000 short-lived audio threads in four minutes had filled its 512-entry table.

## BeamNG.drive: the file you add yourself

BeamNG.drive 0.39.4.0 starts its menu through Ultralight, which looks for `ultralight/icudt67l.dat` next to the game and ends the game with "Failed to load ICU data" when it is missing. The game does not ship it, and Porthole does not supply it. It is ICU 67.1's standard little-endian data:

1. Download `icu4c-67.1-data-bin-l.zip` from the official ICU release, <https://github.com/unicode-org/icu/releases/tag/release-67-1>, and unzip it. The file inside is `icudt67l.dat` (28,395,840 bytes; SHA-256 `af885b67d3c99e6fa7d7eefbd20c3e22d23f894466549a97810dd5a278cd0957`).
2. In the Files app go to Porthole, `wine`, `drive_c`, `Program Files (x86)`, `Steam`, `steamapps`, `common`, `BeamNG.drive`. Make a folder named `ultralight` there (lower case) and put `icudt67l.dat` in it.
3. Start the game from Porthole.

Known limits (early support, tested on one iPad Pro M4): a big map loads in one to three minutes, and shaders for anything new are compiled during the load (the game keeps them, so the next load is faster); big maps use up to about 5.9 GB, close to the memory limit; the game's own online login fails with a certificate error and some menu fonts are missing. Switching to Borderless works. Wine's own shader compiler was tried in place of the game's and cannot read its material shaders, so the game keeps its own.
