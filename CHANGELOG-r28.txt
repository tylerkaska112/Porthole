PORTHOLE - changes on branch merge-r28 (after 1.2.0; running notes, keep updated in the same commit as each change)
=====================================================================================================================
Ported from upstream Madeira (willfaust/Madeira, GPL-3.0-or-later) where theirs was better than ours and nothing of ours breaks.

ADDED
* itch.io: games shipped as .7z install (Madeira's streaming .7z reader, itch_7z.c: LZMA, LZMA2, BCJ and the other branch filters, Delta, Deflate, Copy; encrypted, PPMd and BZip2 archives are refused with a reason). A zip or .7z inside a download is unpacked where it lies. Zip files keep using Porthole's own reader (same ZIP64, CRC and path checks). A .rar is reported as unsupported. Tested on a Mac with LZMA2 and BCJ+LZMA archives (identical bytes).

* Gyro aim and turbo (Madeira's PadAssist): per game in Game details, off until turned on. Gyro aim adds the controller's rotation (DualSense, DualShock 4, Switch Pro) or the device's own gyro to the right stick, or moves the mouse when the game gets no controller from the pad (always, or only while holding LT / LB / RB; twist or tilt to turn; sensitivity, anti-dead zone, inversion). Turbo repeats chosen buttons (A B X Y LB RB LT RT) 5 to 30 times a second while held. Applied once to player 1 before the Xbox pad, the DualSense report or keyboard-and-mouse mode sees the sample. Unverified on a device.
* JIT messages (Madeira PR 532): when the built-in helper does not start or times out, the message now points to StikDebug as another JIT method in Settings.
* Share this game's setup (the idea is Madeira's Share Setup): Game details can write a game's launch options, per-game settings, engine choices and lines, and saved controls into one ".portholesetup" file or one line of text, and apply one from a file or the clipboard. The apply sheet lists everything first (engine lines in full) and warns when the setup was made for a different game. Nothing personal is in it (no program path, account or play time).
* Graphics card the game sees (Madeira's GPUCards): per game in Game details > Compatibility. One choice (NVIDIA RTX 3060 or GTX 1060, an older GeForce 7900 GS for Direct3D 9 games, AMD RX 6700 XT or 580, Intel UHD 630, or this device's own GPU) names the same card in Direct3D 9/10/11/12, Windows' adapter list and NVAPI. Off by default.

* EA app as a sixth store (Madeira's SwiftEA protocol code, written into Porthole's Stores tab): sign in on EA's own page, the account's PC games with covers, install straight from EA's servers (range requests into the game's folder, CRC-checked, with pause/resume, update, repair and uninstall; the same Downloads page, background keep-alive and Live Activity as the other stores), and start games without the EA app: Porthole asks EA for the game's licence for this machine, writes the EA app's registry keys and environment, and answers the game on 127.0.0.1:3216 the way the EA app's service would. The graphics card chosen under "Graphics card the game sees" is also the one the licence is made for. Games with EA's kernel anti-cheat (Battlefield 2042 and later, EA SPORTS FC, Madden) cannot run; cloud saves, friends and the overlay are not supported. Installs go to the C: drive (not the SSD library) for now. The EA logo is not shipped: the store shows a plain "EA" mark. Upstream never ran this Swift on a device and neither have we: sign-in, install, Play, pause/resume, update, repair and uninstall all need a device test, and the first Play of a game with a Core folder tests the machine hash.

* Donor memory (Madeira's MadeiraMemoryHost): a new small extension, F4MemoryHost (bundle id <app>.MemoryHost, so a full install uses five App IDs; it can be left out when signing like the others, see docs/INSTALL.md). Settings > Engine options > Donor memory (2, 4 or 6 GB) lets a game's memory live in RAM that is billed to no app, which is how the memory-hungry games (Sons of the Forest at 6.1 GB, Red Dead Redemption 2) get past the app's limit. Off by default. The engine side was already in the libraries; only the extension was missing. Unverified on a device: iOS decides whether the memory is really free.

* Madeira's tested setups (GameRecommendations: 77 lists, 51 of them for single Steam titles; RDR2, GTA V, Ghost of Tsushima, God of War, Horizon, Dark Souls, Fallout, Crysis ...): a game page Madeira has a list for shows "Madeira's tested setup" under Performance, with what it contains and a button. Nothing is applied by itself (Madeira applies them on first install; Porthole asks). Applying replaces the game's engine lines (the previous ones are kept for Undo) and sets AVX, the NVIDIA card choice, Wine's C++ runtime, fast sync, the screen size and the Wine desktop where Porthole has a place for them; the FPS limit, aspect/scaling and "services first" are listed as not applied. The lists were tuned on Madeira's builds and are untested on Porthole's engine.

ENGINE
* Engine merged with Madeira up to 1608a25 (192 commits after c2c1b03): FEX (16 KB SMC traps, rpmalloc spans), wine (per-process directory cache, SetThreadIdealProcessorEx, iOS directory reads), DXMT, Dock (Steam client service before the CEG request, CEG retry). Engine id 31477ff-r0, so every compatibility badge starts again. Built and linked; not run on a device. See patches/MERGE-2026-11-03.md.

* Dock sessions (Madeira's DockGameSession): Wine's service manager starts in a Steam game's session when its launcher registered an automatic-start service (or the game's env.MADEIRA_DOCK_GAME_SCM says so), and that session runs fastsync instead of madsync; a game folder with a 32-bit program holds one guest-window placeholder for the game's own 32-bit programs only; a 64-bit title beside 32-bit helpers takes donor RAM first. All logged as [dock-game-scm] / [dock-wow]; env.MADEIRA_DOCK_GAME_SCM = 0, MADEIRA_WOW_HOLD_FOR_GAME = 0, MADEIRA_DOCK_X64_TITLE = 0 and MADEIRA_DOCK_GAME_SCM_FASTSYNC = 0 switch the parts off. Unverified on a device.
